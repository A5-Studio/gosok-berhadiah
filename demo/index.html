Gosok Berhadiah — Live Demo

A digital scratch-card campaign. Merchants scratch cards to win commission cash or a ticket for a live-streamed grand-prize draw. Production ran on Google Sheets, an Apps Script JSON API and a WordPress widget.

All data is synthetic. Backend is simulated in-browser by a JS port of the Apps Script code.
Quick start: tap a test number to open it in the merchant widget

Merchant widget

This is the production WordPress/Elementor widget, unchanged. Its fetch() calls to the Apps Script URL are answered by mock-api.js.

  1. Tap a quick-start number above, or type one into the widget and press Cek.
  2. Tap Gosok di sini sekarang! The redeem call picks the prize on the server before you scratch.
  3. Drag across the grey layer. Once about 50% is cleared, the card reveals the prize and the celebration screen opens.
  4. Watch the API inspector: lookup, then redeem, then a fresh lookup when you close the popup.
  5. Open Data tables to see the new REDEMPTIONS / KOMISI_DISBURSEMENTS / DRAW_ENTRIES rows.

Numbers starting 80000000 are the backend's own dummy-mode test UIDs. Their outcomes are fixed and they can be re-scratched. Numbers starting 0812-0000 go through the production path and the real weighted picker.

Live-draw operator panel

The panel below is the production draw_operator.html. Pick a wave, choose a prize, press STOP, and it calls draw_pick_one. Only draw-ticket holders who registered in the attendance form (FORM_LIVE) are in the pool. The buttons here call the other operator endpoints directly.

One-by-one picks and draw_run can be mixed: draw_run only awards the slots still open and skips anyone who already won this wave.

These are the in-memory sheets the JS port reads and writes. They mirror the Google Sheets tab names and headers. Rows highlight when they change, and state persists in localStorage.

How this demo works

The real system has 4 parts. Raw Order Data lives in Google Sheets. A 2-hourly syncOrders() mints scratch cards for eligible orders (Saku = 1 card, Android = 2). A doGet JSON router serves the widget and operator panel. A weekly job handles disbursements.

Here every .gs function the endpoints touch is ported 1:1 to demo/mock-api.js and runs against a JS object shaped like the workbook. That covers eligibility, the weighted picker with daily quotas, idempotent redeem, wave assignment and the attendance-gated draw. The two HTML frontends are the original files, with window.fetch patched underneath them.
